# GRAVIYX

The GRAVIYX marketing site.

A client-rendered React single-page app built with Vite, routed with TanStack Router and styled
with Tailwind CSS v4. It builds to static files and is deployed to GitHub Pages.

## Stack

| | |
| --- | --- |
| Framework | React 19 |
| Build | Vite 8 |
| Routing | TanStack Router (file-based, `src/routes/`) |
| Styling | Tailwind CSS v4 — CSS-first, configured entirely in `src/styles.css` |
| Motion | `motion/react` |
| Language | TypeScript, strict |

There is no server. Every route is rendered in the browser, so the build output is plain HTML,
CSS and JavaScript.

## Getting started

Node.js 20 or later.

```bash
npm install
npm run dev      # http://localhost:8080
```

## Scripts

## How it is put together

```
src/
├── main.tsx              mounts the router into index.html
├── router.tsx            creates the router from the generated route tree
├── styles.css            the design system — all tokens and utilities live here
├── routes/               one file per page; the filename is the URL
├── components/
│   ├── home/             the Home page feature (page, parts, copy, context)
│   └── site/             shared chrome and primitives (Header, Footer, Reveal, ...)
└── lib/
    └── seo.ts            the per-page title and description map
```

`src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin from the files in
`src/routes/`. **Do not edit it by hand** — it is regenerated on every dev run and build.

### Adding a page

Create `src/routes/<name>.tsx` exporting a `Route` via `createFileRoute("/<name>")`. The URL is
the filename. Then add its title and description to `ROUTE_META` in `src/lib/seo.ts` — that map
is the single source of per-page metadata.

### The design system

Everything visual is driven by `src/styles.css`. The palette is strictly monochrome — Ink,
Paper and a steel ramp — with no accent colour, per the brand guidelines. Read
`src/components/home/home-context.md` before changing anything neumorphic; that material is a
deliberate, scoped exception to the hairline rule and it has specific constraints.

## Deployment

Pushing to `main` triggers `.github/workflows/deploy.yml`, which builds the site and publishes
`dist/` to GitHub Pages. The workflow adds a `404.html` copy of `index.html` so deep links
resolve, since Pages has no SPA rewrite of its own.

`vite.config.ts` sets `base: "/"` because the site is served from a custom domain at the root.
If it is ever moved to a project subpath, that value must change to match or every asset will
404.
