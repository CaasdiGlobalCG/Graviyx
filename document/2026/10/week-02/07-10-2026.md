### Why

- The site was built on an Operon palette with a neon-green accent, a display font that was never
  actually loaded, and a 404 page that rendered unstyled. None of that matched the supplied brand
  book, and the brand book is explicit: *"The GRAVIYX palette is intentionally monochromatic… No
  decorative accents are introduced."*
- `--font-display` was set to `"NeueHaasGrotesk"` but only Inter was ever loaded, so **every heading
  on the site was rendering in the Helvetica fallback**.
- `prefers-reduced-motion` was honoured for CSS only. Every `motion.*` animation and both SMIL
  markers ignored it.
- Three animations moved layout or paint properties (`height` in two places, `background-position` in
  two keyframes), which the repo rules forbid.
- The favicon was the neon-green accent, not a Graviyx mark.

### How It Works

**Tokens.** `src/styles.css` is the single writer of the design system. Brand palette tokens
(`--ink`, `--paper`, `--paper-2`, `--steel-90…15`) feed semantic aliases (`--bg`, `--surface`, `--fg`,
`--muted`, `--meta`, `--border`) so the ~150 existing `bg-bg` / `text-fg` class usages kept working
while their values changed to brand values. `@theme inline` maps everything into Tailwind.

**Honesty about values.** The brand PDF publishes exactly one numeric colour — Paper `#FAFAF7`.
Ink and the six steel neutrals have **no printed hex, RGB, CMYK or Pantone**. Ink is therefore taken
from the supplied official logo files (which are pure `#000000`), and the steel ramp is derived and
labelled `DERIVED` in the file header. Nothing is presented as brand-published when it is not.

**Assets.** `GRAVIYX WORDMARK.png` and `GRAVIYX COMPLETE LOGO.png` are RGB with a white background
baked in, so they cannot sit on Paper. They are keyed luminance-to-alpha instead — the correct
unmatting for a black-on-white asset, which preserves anti-aliasing exactly. `Graviyx_Brand_Logo.png`
turns out to store its wordmark as fully transparent black (invisible in reality; only alpha-ignoring
renderers show it), so the wordmark comes from the standalone file. The favicon is regenerated from
the symbol, in Ink on Paper.

**Motion.** A kit in `styles.css` (`--motion-instant/fast/base/slow/scene/draw`, `--ease-signal`,
`--ease-cut`) is the only place durations and curves live. `--ease-signal` is the curve the
components were already using inline, now formalised. Reduced motion is handled globally by
`<MotionConfig reducedMotion="user">` in the root route, which covers every `motion.*` animation;
the two SMIL `<animateMotion>` markers are gated individually because Motion cannot reach them.

**The no-logic-change proof.** `Graviyx-Site` had no git history, so a nested repo was created

`Reveal.tsx`'s header/JSDoc/constants. `DealTimeline.tsx` carries the single deliberate exception:
`height` → `scaleY` on a `useTransform`, required to stop the scroll fill animating a layout property.

### Why

The site had a brand system but no committed design direction, and its content was v1.0
marketing prose rather than the v2.0 plain-language edition. The client wanted a direction
chosen from real options, then applied consistently.

### How It Works

**Neumorphism, as a scoped exception.** The repo rule is "structure with hairlines, not
shadows"; neumorphism is made entirely of shadows. It is permitted, but constrained:
- One surface set serves two canvases. `neu-canvas` (Paper-2) and `neu-canvas-dark`
  (steel-90) each re-point `--neu-surface`, `--neu-light` and `--neu-dark`, so
  `neu-raised`/`neu-flat`/`neu-pressed`/`neu-inset`/`neu-control`/`neu-field` work unchanged
  on either.
- **The dark canvas is a dark grey, never pure Ink.** Black leaves no room for a shadow
  darker than itself, so the effect collapses into a flat rectangle.
- **A surface's background must equal its parent canvas exactly**, or the paired shadows read
  as a drop-shadowed box. Every section rendering a `neu-*` surface carries a canvas class.
- **Both secondary text tones are re-pointed on the light canvas** — `--muted` to steel-70
  (~9.4:1) and `--meta` to steel-50 (~4.7:1). steel-30 is ~2.5:1 on a mid-tone and fails. The
  token-level fix also covers SVG `fill="var(--meta)"`, which a class-level fix would miss.
- No Tailwind `shadow-*` anywhere — that scale is blue-black and reads as a second system.

### Four defects found and fixed, three of them mine

1. **Content was invisible.** 73 elements per page carried inline `opacity:0` and depended on a
   JS `whileInView` observer to come back. If it never fired — JS disabled, hydration failure,
   an embed that does not scroll — the page rendered blank. `Reveal` is now CSS scroll-driven
   with a **visible base state**; both maps render unconditionally; 20+ call sites swept.
2. **Every decorative grid was drawing solid, not at 5%.** `color-mix(in oklab, currentColor
   5%, transparent)` cannot be resolved at build time, so the compiler dropped the percentage
   and emitted a solid line — ~20× too heavy. Fixed with `--veil` / `--veil-strong` tokens
   re-pointed per surface.
3. **The focus ring was being destroyed.** `:focus-visible` used `box-shadow`, which lives in
   the base layer, so any utility setting `box-shadow` overwrote it. Now an outline.
4. **A 2.1 MB scratch file** an agent left in the repo root got committed. Removed, with a
   `.gitignore` guard.

### Verification

`tsc --noEmit` clean · `npm run build` passes · all 19 routes 200 · every page carries a dark
neumorphic section · zero `shadow-*` · zero content-hiding `opacity:0` · firewall proven on the
three stateful pages (Contact, Login, Post-a-Requirement) across 14 patterns, all counts
identical.

**Not verified: visual rendering.** There is no headless browser in this repo, so every
geometry, shadow and contrast claim is DOM, CSS-emission or arithmetic — not seen.

now alternates light/dark through its middle. And **"Where we serve" and "The ecosystem"** —

### Files Changed

| File | Change |

| `src/components/home/HomePage.tsx` | 3 sections to `neu-canvas-dark`; the two carried-over sections rebuilt as raw `neu-canvas` sections with `Reveal from` wrappers; `Section` import dropped |
| `src/components/site/IndiaCoverageMap.tsx` | `border-y` → `neu-raised`; `bg-bg` and `bg-surface` removed so the raised surface shows through |
| `src/components/site/EcosystemDiagram.tsx` | Same; node rects `fill="var(--bg)"` → `fill="var(--neu-surface)"` |
| `src/styles.css` | `neu-canvas` now re-points `--meta` as well as `--muted` |

### Why

The client asked for dark bands on 3, 5 and 7, and for both carried-over sections to use the
neumorphic material.

### How It Works

**Grounds.** `neu-canvas-dark` is steel-90 — a dark grey, deliberately not pure Ink, because
black leaves no room for a shadow darker than itself. It re-points the neu tokens *and* the
semantic set the way `surface-ink` does, so headings inherit Paper and no per-node colour class
is needed.

**The components were neutralised**, not forked. Their own backgrounds fought the canvas — the
map's `bg-bg` and the diagram's `bg-surface` sat a shade off the raised panel — so those came
off and the diagram's node fills moved to `var(--neu-surface)`. No copy or structure changed.

### A regression this created, and the systemic fix

Moving those sections onto a light neumorphic canvas put **18 `text-meta` occurrences on a
mid-tone ground**, where steel-30 (`#9c9c97`) is about **2.5:1 — a fail**. `neu-canvas` was
re-pointing `--muted` but not `--meta`.

It now re-points **both**: `--muted` to steel-70 (~9.4:1) and `--meta` to steel-50 (~4.7:1, AA).
The two-step hierarchy survives; it just moves into the range a mid-tone can carry. Fixing it in
the token rather than per-node also covers every SVG `fill="var(--meta)"` — the map's graticule
labels and the diagram's node codes — which no class-level fix would have caught.

### Verification

`tsc` clean · build passes · all 19 routes 200 · Home is 4 dark + 6 light neumorphic sections ·
15 raised panels · zero `shadow-*` · zero content-hiding `opacity:0`.

## Session 4 — Parallax: a pinned hero and side reveals

### What I Built

A parallax treatment across the site, in **CSS scroll-driven animation rather than JavaScript**,
so nothing is scroll-jacked and the whole thing degrades to a plain, legible page where it is
unsupported or where the visitor has asked for reduced motion.

### Files Changed

| File | Change |
| --- | --- |
| `src/styles.css` | `hero-pin` + the sibling rule, `hero-depth`, `reveal-left` / `reveal-right` and their keyframes |
| `src/components/site/Hero.tsx` | Carries `hero-pin` and `hero-depth` — one change, inherited by all 17 pages |
| `src/components/site/Reveal.tsx` | Gains `from="bottom" \| "left" \| "right"` and an `x` travel distance |
| `src/components/home/soft-machine.parts.tsx` | The six primitives gain and forward a `from` prop |
| `src/components/home/HomePage.tsx` | Alternating directions throughout; hero pinned |
| `src/routes/*.tsx` (17) | Every `Reveal` given a direction |

### How It Works

**The pinned hero.** `position: sticky` holds the hero while the page scrolls over it — that
layering *is* the parallax: the hero is one layer moving at zero rate, the content another at the
scroll rate. Sticky occupies its normal space in the flow, so nothing leaves the document and the
page height is unchanged; only paint order changes.

The sibling rule is what makes it work: a sticky element is *positioned*, so it would otherwise
paint **above** the following non-positioned sections. Lifting those siblings to
`relative; z-index: 10` puts the content back in front, still below the fixed header at `z-50`.

**Side reveals** share the existing contract exactly — base state visible, animation attached only
inside `@supports (animation-timeline: view())` and `prefers-reduced-motion: no-preference`. Only
the axis differs. Travel is 48px, deliberately smaller than the vertical offset would be, because
horizontal motion is more noticeable and more likely to cause discomfort.

**Forms are treated differently, on purpose.** A form sliding in from a side while you fill it in
is a usability defect, so on Contact, Login and Post-a-Requirement the form panel keeps the bottom
reveal and every input, select, textarea and label is untouched.

### A real defect found in review and fixed

Contact's enquiry-type fieldset had been given a side reveal, but it sits *inside* the form panel
whose padding is 24–36px — so a 48px horizontal travel would **overhang the panel's own edge** as
it scrolled in. Back to the bottom reveal, with a comment saying why.

### Verification

`tsc` clean · build passes · all 19 routes 200 · every page carries `hero-pin` **except `/about`,
which correctly has none** (the v2.0 About section has no hero) · zero `shadow-*` · zero
content-hiding `opacity:0` · firewall proven on the three stateful pages across 14 patterns.

### Why

The bar read heavy, and the cause was measurable rather than a matter of taste: **`btn` is 13px/26px

### How It Works

- The nav sits immediately after the mark, so the eye reads one continuous left-to-right line.

  transform, never a layout property.
- `Login` carries the nav recipe, so it belongs to one system.
- A hairline separates the nav from the actions, giving the eye one place to land.
- The mobile panel uses `divide-y`: one hairline between items, none dangling under the last.

## Session 7 — The daily-documentation convention changed

### What I Built

The daily log moved from `Documents/dd-mm-yyyy.md` to a date-nested path:

```
document/YYYY/MM/week-NN/dd-mm-yyyy.md
```

So today's file is `document/2026/10/week-02/07-10-2026.md`.

### Files Changed

| File | Change |
| --- | --- |
| `.devin/rules/main-instructions.rules.md` | The documentation rule and the quick-reference entry |
| `.devin/rules/frontend-design-standards.rules.md` | Two entries |
| `.devin/skills/page-redesign-variants/SKILL.md` | Its documentation step |
| `document/2026/10/week-02/07-10-2026.md` | This file, migrated by `git mv` from `Documents/07-10-2026.md` |

### How It Works

**Weeks run Monday to Sunday, and the week containing the 1st is `week-01`.** So October 2026 runs
`week-01` (01–04), `week-02` (05–11), `week-03` (12–18), `week-04` (19–25), `week-05` (26–31).
07-10-2026 is a Wednesday in `week-02`.

Any missing `document/`, `YYYY/`, `MM/` or `week-NN/` folder is created as needed.

### Two things worth recording

1. **There is no documentation *skill*.** The convention lives in the rules, so that is where it was
   changed — three rule files plus the one skill that restated it.
2. **`.cursorrules` could not be updated.** It is excluded by the parent whitelist
   (`C:\Caasdi\.gitignore:7: /*`), so the file tools cannot read or write it. It is a legacy Cursor
   file; the `.devin/rules/` files are what this tool actually injects. Worth updating by hand, or
   whitelisting, if it still matters.

### Verification

original (moved by `git mv`, not rewritten) · the empty `Documents/` folder removed.
